# 演进记录

## 2026-10-26 首版

目标：把工作目录下的样本（`天象预报 2024年12月.docx`）变成一套能对**任意年月**复现的流程。

### 一、先量格式，再写代码

没有靠眼睛估，而是把 docx 拆开量：A4 21×29.7、左右边距 3.175、上下 2.54、宋体+Calibri 10.5 pt、两端对齐、kerning 2、单倍行距零段距、全文无加粗、全角冒号、角分用 U+2019、望远镜目标用 Word 自动编号。这些值全部写进 `docx_writer.py` 并用 `tests/test_format.py` 锁住（拿样本自己的文字重跑生成器，逐段比对）。

### 二、历算先对样本，再对外部历表

1. 先用样本当"第一参照"：2024-12 的月相五条、近/远地点、节气、八个行星的星座——全部对上（月相分钟级，节气到秒）。
2. 但样本只有一个月，且数据来源不明，于是另起一条独立链路（`docs/validation/`）采集外部历表：AstroPixels、NASA GSFC、天文通（`api.knockdream.com`）、NAOJ、HKO、IMO。用 2025-03 与 2026-11 两个月做成参考文献表，再写成 `tests/test_accuracy.py`。

**这一步立刻抓到一个真错误**：水星大距用"视黄经差极大"是我为贴合样本 15:10 做的选择，而 2025-03 的三家外部源一致对到"角距极大"（14:00）。同一个事件两种口径差 4 小时以上——说明前者是对单一样本的过拟合。已改回国际通用口径。

### 三、修掉的实现缺陷（都记了原因，防止回退）

| 现象 | 根因 | 修法 |
|---|---|---|
| 火星"升起于西方" | 取的是**天亮前**的方位角 | 改取升起那一刻的方位 |
| 木星冲日提示"日落后位于西北方" | 取方位用了月初某时刻而非日落时刻 | 改取日落+1h |
| 2024-12-01 月掩心宿二标"可见" | 只判天体高度，没判太阳高度 | 加太阳 < -6° 条件 |
| 火星/海王星"留"落到错误日期 | 0.5 天步长 + ±0.05 天差分太粗 | 1 小时步长 + ±0.02 天中心差分 + 二分 |
| "顺行，7日留后转逆行"自相矛盾 | 当月有留时仍用整月平均运动方向 | 改用留**之前**的方向 |
| 水星"前半夜5时前后升起" | 没区分凌晨/前半夜 | 按升起时刻分档措辞 |
| 生成的 docx 比样本撑开一倍 | python-docx 自带模板是 1.08 倍行距 + 8 磅段后 | Normal 显式写 spacing=0/0/single |
| 生成的 docx 比样本更紧 | 我额外关掉了中西文自动间距 | 撤掉，样本本来就开着 |
| 望远镜目标序号后空一大截 | 编号默认用 tab 跳到下一制表位 | 改成 `w:suff="space"` |
| 手绘月相"亮面溢出圆盘" | 蛾眉月把亮区画到盘外 | 放弃手绘，改用真实月面照片 |
| 11 月报表里冒出 12 月的事件 | 月份边界按 UTC 切，而报表用北京时间 | 边界改成"当月 1 日 00:00 北京"，用 `_bjt_to_time` 换算 |
| 推荐栏出现空段落（2026-02） | 平淡月份里把月相凑进了推荐，而月相没有文案分支 | 月相/节气/近远地点不进推荐；兜底分支改成抛异常 |
| 2025-03 推荐栏整段清空 | `_observable` 按"事件时刻"判可见，把凌晨才可见的水星大距判掉了 | 区分点事件（月掩/食）与时间窗事件（合月/大距/冲日） |
| 同一目标一个月出现两次（2026-11 木星合月） | 未按身份去重 | 按 (类别, 目标) 去重，保留分高的一条 |

### 四、月相日历图的四次转向

1. 先自己画（Pillow 画圆盘+明暗界线）→ 放大看发现蛾眉月亮面溢出圆盘，且像硬币。
2. 改成截 Star Walk → 站点没有单张图，其月历是 App 内的表格。
3. 改成截 Calendar-12 的整块网格 → 能出图，但带导航箭头、英文相位说明、竖长条。
4. **最终**：取 Calendar-12 的月面照片雪碧图（120×12000，100 张按相位排列，NASA/Goddard 公有领域），按每天算出的相位角取图，自己用中文网格排版。

排版尺度也是按"印刷后多大"反推的：第一版按 232 px 一格画，插入 14.6 cm 宽后星期名只有 3.7 pt、相位名 3 pt，打印读不清；改成 460 px 一格（整图约 3300 px ≈ 226 px/cm）后字号才落到 7~14 pt。

### 五、内容体检是另一类测试

格式测试管排版、数值测试管事实，两者都过了仍可能产出"排版漂亮但内容是空的"
文档——2026-02 就出现过推荐栏里一堆空段落。于是补了 `tests/test_content.py`：
跨 5 个风格不同的月份，检查推荐条目字段非空、标题不重复、清单不重复、
动态行 8 条且格式统一、正文里不出现模板占位符。

### 六、教训

- **一个月的正确不等于通用的正确。** 用第二个独立月份（2026-11）复核时立刻抓到
  UTC/北京时区切月边界的错误，以及平淡月份凑数产出空段落的问题。
- **样本文档是格式基准，不是数据基准。** 拿它校排版没问题，拿它校数值会把领域口径改歪。
- 只有一个样本时，"吻合"很容易是过拟合。必须找第二个、第三个独立参照物，而且要选口径明确的（整点源就按整点判，别按分钟判）。
- UI 层面的"看起来对"不够：火星从西方升起这种错误，只有在把方位角和时刻一起打印出来时才看得出来。
